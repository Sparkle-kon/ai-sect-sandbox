# E4-3：雪谷关外，要等一批南来的暖芦

北岭雪谷、南泽灵田各有独立的 3×3 图页和实际场所。旧图宽高、地块、道路、寒玉井和旧账不变，旧北脉与中坊仅是两条真实出入口。首个合资格的人在旧锚本人实付 8 灵石和 1 株玄土根，到达对应关口，之后按相邻格逐月走；真实走到居所再付 4 灵石和 1 株根，才是当前可驻住的同一人。没有把他复制成留在故里的第二个身体，也没有用人口标签生成劳动。已有合法身份能再次入世；未到的地域不显示当前私账。原三个下界地域加两个实际可走可作的区域，本轮是五个，不把旧上界节点算进九域。

北岭护泉要亲到泉眼、实用一株根，来月才按季节收水。冬圃须母根、水、劳动和成熟时日；缺水确实会枯失。南泽须在潮窗当面开闸，东西两块真实轮田独立；播种、灌溉、南修共用当月的当地劳力和有限水账，南修实扣 2 水。北修用已经实际进仓的南泽暖芦；两地都不因菜单名或传闻自动生货。只生成真实成熟收割的批号，不重复入仓。老寿尽者仍在真实异域原地，原有财富不会落作故乡的遗产。

## 受控原生实跑

独立原生种子 1，北方是实际原角色苏清寒，南方是韩立风。没有编辑钟、坐标、库存或人口，由在原世界实际采根、走路的当事人发出合法动作。T5／T6 旧中坊两人分别当面立约，T14／T17 分别实付登记。T24 北圃得 2 份霜药，南方东田 T32 实收暖芦 2、西田 T38 再收 3。一份待供的货还未成熟、未装船或未到仓时，不会贵在写好了就算进对方仓。

- T47／1004 年十一月才双边实装。北货沿 17 个实际检查点的常路，入冬 T48–50 各月真停不动。南货另实用了 1 份原东田收成，走 19 个检查点的真实背风旁道，多两格。T53 南货已到，仍托管；双方实际收入均为 0。
- T56 两边实到才交换：北方取得暖芦 2，南方取得霜药 2。T57 北方真正从先前交割的那批中用去暖芦 1，余 1，练气进度 80→86。没有在货未到时先发后扣。
- 同一原局另开支线，南边从未装货。北货 T56 实到但未交割，T78 实际越约起返。T83 走回已到的原址格 0 才把同一原始 2 份霜药重新收入原仓，南边始终没有计作新收入。不是按下取消立即回仓。

七个实际节点独立封档并从磁盘严格读回，原生总 1,830,063 字节；T48 读回后实际下一月与直接推进逐字节相同。T47 的原支线保持原样。另验真实冬季过关、走旁路和退出至同一旧址；假跨图、同月反复用工、伪造批货、未到货使用、个人已亡和跨身份命令都不能成事。Utility 与严格认知 JSON 都执行同一地理、成本及货源判断，模型只复制许可，测试使用模拟提供者不发真实外部请求；化身预约不提前扣钱或库存。

界面仍只用原有手机首页两项，在原「世界」折叠能看到真实旧锚；人真进异图时才换本地地图，既不同时画旧屋里的人，也不向另一图显示本人未见信息。沿用现有可玩流程，未将这一批机制同步到现有手机试玩。360×680 云端 Chromium 实际验证了旧锚折叠、入世与两个各自地图：十二月雪谷没有已经关闭的直脊选项，预约背风台后仍在原关，过一月才走到实格，未重扣进关费；南泽所见只有当下的关口和可走邻格。没有横向溢出。这次浏览器核查的是地理与操作，货运与生产由前述原生测试走实，不冒称实体手机测试。

## 复现

在仓库根目录用既有依赖跑实际控制与旧界路回归：

    npm run test -- tests/frontierMovementNative.test.ts tests/frontierProduction.test.ts tests/frontierTradeNative.test.ts tests/frontierScopedUiNative.test.tsx
    npm run verify

另起独立的证据目录（必须此前不存在），实际生成七组便携档和两支读验记录：

    ./node_modules/.bin/vite-node scripts/frontierNativeAcceptance.ts ./雪谷灵田-本次

机器可读的实跑日期、支付／入仓、货路归还及原始每个便携档摘要见 docs/era-e4-3.ndjson。纸上路线不等同于实走；只有记录中确实经历的月份和范围是已验证结果。
