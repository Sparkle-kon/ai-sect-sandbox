# E4-2：八份长局历史都保留，再从其中一份真实续演

新增的是**独立本地历史包和明确的离线续跑**，不是给手机的原时间线一口气塞入全部历史。原来的普通 JSON 8 MiB、单份年代世界 32 MiB、浏览器可续源 128 MiB、单次浏览器目标 1,200 月均未改变。独立包同样只接受合格的 32 MiB 单帧，以 1 MiB UTF-8 原字节页分块，逐页与整帧核对 SHA-256，逻辑保留内容（历史与新头合计）上限 192 MiB。可以查回各原分支的准确日期；一段离线续跑仍明确输入 1–1,200 月，不自动推进、剪去旧史或把作者线当原生。原始有 .era 清单与分卷时，独立验证后保留原清单和原始世界字节，不用新 JSON 伪装旧原件。

## 实验：同一批八份旧原生快照

独立以历史 E3-1 原生规则从既有严格年代重建 T1201–T1208，完整保留每一份。T1201 历代 497、在世 490，T1208 历代 503、在世 496；没有人口上限或填充合成人。原 T1201 在另一历史 E1-10 包的原摘为 9962d29f…，E3-1 规范化后是 bb615a03…；八帧比较使用后者及其实际续演，不把两份同刻文件冒作同字节。旧准确 T1209 原生 18,465,728 字节，原规则直接跑与读回再跑 SHA-256 同为 ad95d046cf3ebfbf27fcf53e8f5dd3265ed7a9d271aacd54542ea57839fd6a21。

| 相同物理输入 | 旧 128 MiB 原源操作（读取+封存进程） | 新独立格式（建包／严格逐帧读回各独立进程） |
| --- | --- | --- |
| 实际七帧，127,494,893 字节 | 接受，5,633 ms；峰值 RSS 1,039,764 KiB | 接受，5,651／3,135 ms；峰值 520,548／582,804 KiB |
| 实际八帧，145,900,820 字节 | 按原 134,217,728 字节拒绝，7,227 ms；峰值 1,100,744 KiB | 八份全部接收并读回，7,530／6,652 ms；峰值 552,856／621,684 KiB |

旧实测同物理输入但历代对象在内存组原时间线，新实测逐帧读写并采用独立包，路径不是等价用例；其它并行构建也会影响耗时，不据表承诺速度倍率。新七／八帧分别 125／143 页、整体 127,508,740／145,916,508 字节（包含目录和小清单）。**这组相邻真实世界没有共享固定原字节页，没有压缩收益。** 真正相同的内容会被保存一次，原引用仍都存在，已在两个实际分支引用的可重复小测试中核验。

八帧逐一审核后，从实际 T1208 按当前新规则显式离线续一月，物理发布第二版、T1209，以该规则的独立直接下一月得同样 SHA-256 25308ca62cfec39d00c50f38c2239503f17932c52edffa313c3a0367fff23e85；不是声称与历史规则结果相同。累计有据保留 164,352,844 字节，T1201–T1208 原分支全在，续前续后抽取原 T1208 仍完全相同。从旧令牌再次续跑明确拒绝。

## 故障与查人是两次独立验收

同一套本地 POSIX 文件系统上，共享只读对象用排它原子链接发布，已暂存页与发布头分开，旧头不被替换，没有因进程强制退出而留下必须人工清除的锁。独立进程在新头已同步、真正发布前被强制结束，旧令牌与对象仍保持；两个实际进程争同一封印只有一个成功，第三个新进程实读成功。篡改最新页/头会拒绝而不是跳过、冒称回到以前或覆盖原件。暂存未引用文件不会变成可续头，此版不自动清理；没有测试机器断电或网络盘行为。

另做严格独立名册：原 T3634 的 21 条角色中 15 在世，加 1,200 条合成分析身份，1,221 历代／915 在世，不是上面八个自然帧，更不是增加游戏人口上限。真实导入和逐字节抽出原生 1,595,148 B 加原清单 567 B。新进程首读加严格校验 80.073 ms，20 次重复 p50/p95 为 27.355／36.296 ms；各 500 次名册／同名／旧人有据／新人无据／Canvas 数据投影的 p95 为 .578／.652／.105／.065／.620 ms，实际在世投成 15 组，旧同名没有覆盖新人身份。云端 Node 查询链峰值 415,384 KiB；不是 Android 绘制、帧率或设备内存实测。

## 复现

在本地 POSIX 文件系统使用已有依赖的仓库，档案和提取输出都使用**此前不存在**的路径：

    node --expose-gc ./node_modules/vite-node/vite-node.mjs scripts/detachedCampaignCli.ts build ./导入计划.json ./独立档案
    node --expose-gc ./node_modules/vite-node/vite-node.mjs scripts/detachedCampaignCli.ts audit ./独立档案
    node --expose-gc ./node_modules/vite-node/vite-node.mjs scripts/detachedCampaignCli.ts extract ./独立档案 original 1208 ./原T1208.json
    node --expose-gc ./node_modules/vite-node/vite-node.mjs scripts/detachedCampaignCli.ts continue ./独立档案 1
    node ./node_modules/vite-node/vite-node.mjs scripts/verifyDetachedArchiveCas.ts ./发布故障验收-本次

输入计划格式 ai-sect-detached-import（版本 1）：给定 timelineId、原构建 sourceRuleVersion、active.branchId/tick/sha256、branches（id、label、可选父支和分歧刻、原顺序 snapshots）。各快照明确提供 kind、tick、year、month、bytes、原 sha256，kind=native 配 file，kind=era 配 manifest 和完整 parts；路径相对计划，或者用已知绝对文件路径。不能只给日期或让程序重算伪造原档。实际留有 .era 的原清单，可用 extract-source 单独写到新文件。若保留 nextBranchNumber 一并提供；不替玩家自动扩大旧支线数量。continue 可附 audit 确认的 revision 与 seal，确保复核的头没有变。在输入/缺页/错误规则/空间错误时不自动改写旧历史。

历史原八帧复验：把 scripts/exactLateHeadArchiveProof.ts 与 scripts/measureLegacyCampaignBoundary.ts 放入独立的 E3-1 提交 55d4b8974a5d942bd51cefa8d68f7d5d9d530542 检出目录，使用原 E1-10 确凿 T1201 .era 及五个实际分卷。前者接受新输出目录、原清单、所有分卷；后者依次接受已生成的实际原档目录、7 或 8、此前不存在的报告文件（见命令自身用法）。它们固定历史指纹、逐月实际验证，不会把新 E4-2 引擎当作该历史来源。机器可读实际记录见 docs/era-e4-2.ndjson。
