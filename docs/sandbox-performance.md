# 千人舆图：性能与同画面复验

这一轮不改地图雾权、移动结算、角色上限，也不改手机首页的两个固定入口。App 将人物引导与档案桥集中；舆图先按真实活动角色建立一次候选索引，仍用原生读法确认每一个在途位置。御剑在开画前准备实际弧线，动画只改在飞的角色；静止后归还原位置数组和静态标记计划。移动中的聚类仍走原逻辑。

## 同一输入，优化前后比对

在同一 Node 24.22.3 环境用同一脚本，先跑旧版、新版，再倒序各跑一次。样本为 48、526、1221 名合成压力演员；两队共四名巡礼者的在途位置来自实际原生签约与行进，不伪造已授权位置。三个视角覆盖 360、390、1440 像素。每轮 27 个场景的授权名单、投影位置、标记和鼠标／触屏命中摘要，以及可见计数均一致。

1221 人、390 像素、2.35 倍时，下面是单次**地图视野投影及标记规划**的毫秒数，格式为 p50 / p95：

| 视角 | 第一轮旧 → 新 | 第二轮旧 → 新 |
| --- | ---: | ---: |
| 全图 | 0.443 / 0.542 → 0.307 / 0.409 | 0.501 / 0.786 → 0.311 / 0.521 |
| 迷雾开启、能看见原行路点 | 0.401 / 0.488 → 0.058 / 0.116 | 0.365 / 0.408 → 0.062 / 0.127 |
| 迷雾开启、在另一地 | 0.429 / 0.498 → 0.078 / 0.176 | 0.207 / 0.349 → 0.078 / 0.151 |

这些是 Node 数据投影和规划的耗时，不是浏览器的完整绘制帧率或实体手机成绩。其余视角包含时序波动，个别场景没有提速，不能把表里的降幅推广到每一帧。在 1200 名可见、只有一人真正飞行的独立受控测试中，飞行动画的位置更新由每帧查询全体、复制全表改为只改这一人；动态聚类不是常数时间。

使用本仓库依赖复跑：`./node_modules/.bin/vite-node scripts/mapRosterBenchmark.ts`。比较时把同一脚本放在两份源码中独立运行，先核对摘要和计数，再查看耗时。

## 首次载入与完整产物

使用同环境的两个生产 Vite 构建，逐个读取产物的 UTF-8 字节，遍历 HTML 入口、样式和静态导入闭包。围城实景的卡片按需加载，没有真实围城的地图不会等它加载。飞升证据的读取和原生结算拆开，两版最终构建检测均无循环分块警告。

| 统计 | 上一版 | 本版 |
| --- | ---: | ---: |
| 首屏静态闭包资源数（含 HTML、CSS） | 65 | 64 |
| 首屏未压缩字节 | 2,146,223 | 2,147,960 |
| 首屏逐文件 gzip 字节 | 736,967 | 736,382 |
| 首屏逐文件 Brotli 字节（质量 5） | 678,463 | 671,841 |
| 完整产物未压缩字节（包括懒加载和 Worker） | 7,613,277 | 7,627,009 |
| 完整产物逐文件 gzip 字节 | 2,551,545 | 2,556,232 |

首屏少一个资源，压缩传输量下降，完整包没有缩小。这是静态依赖分析，不是设备上的网络瀑布或首绘测速。
