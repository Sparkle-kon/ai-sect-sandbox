# E4-9：重开一份长局，再到井边走一个月

六千年试验显示，单次原生严格读档的尾部时间远高于姓名或地图投影的内存查询。这里不为追求速度而放松存档验证。明确接续前，先核封存版本链、原始清单与所见版本；可以确定是错规则、旧凭据或容量已用尽时，立即拒绝，无须先解码整段世界。走到可以接续的一路仍逐份严核原载荷、真实年月、原分支和接续签名；发布前再核同一有效凭据。不改变原生世界规则，浏览器存档也不归这个本地工具管理。

独立 Linux／Node 测量使用同一份有 30 个六千年真实快照、另有一个正常已提交月份的只读接续档。实际保留 22,959,305 B。以已真正存在、但现在比档头旧的凭据试请求，两边各暖身 2 次、正式 7 次：

| 同一失效凭据 | p50 | p95 |
| --- | ---: | ---: |
| 原来先严读所有载荷再拒绝 | 448.66 ms | 901.35 ms |
| 先验封印和实际版本再拒绝 | 1.85 ms | 3.05 ms |

计时只含那次拒绝；首末都全档严审，文件清单、每个字节及有效档头保持一致。这不表示合法全量读档同样加速，也不是手机性能结论。

## 重开不是在一个进程里假装断过

取 E4-8 真存下的 T58834 与 T60034 两个原始便携包，在独立目录建立一条接续副本。第一个 Node 进程真实提交 T60035 后退出；另一个进程严格重新打开，再提交 T60036。两份新头各与当前同规则的原生逐月对照同字节；另从最新严格读回再跑 T60037，仍与直接原生一致。这里的对照是该接续工具的原生 Utility，不套用六千年长跑中指定调息的那条政策。旧源物理文件、两个原始帧及封面逐一通过精确提取核对，没有写回原史。

用不同真实 E4-6 构建请求当前档案续跑，因规则指纹不同明确拒绝。另用当前规则的真实旧凭据、超过上限的月数、同字节数但改过一处的本地载荷、同样损坏的输入便携包分别验证：错误没有产生新的有效接续，不覆盖健康的最后一版。损坏副本的旧凭据可以提前被拒；同一损坏副本用当前凭据必定严格检查并拒绝，不算有效读档。

再另建一个原副本做实际进程中断。原生产线执行真实下个月并同步候选之后、还没发布新档头之前，定点结束子进程（Linux SIGKILL，不声称机器断电）。重新打开仍是 T60034 原头。新进程拿同一有效凭据重试，真正且仅一次发布 T60035，原生候选字节和此前临时候选相同。第三个独立进程再拿旧凭据，明确拒绝，不会另出一版；中断留下的未引用内容不是已发布的游戏档。旧井、水账、采契和实际原货不变。

## 六千年后，真的付钱勘了一次旧井

从精确 T72034／7003 年十月原档选当时在世且就在原井边的闻春岚，使用原入世流程另开一支。确认入世扣神识 24；选「勘测」并排到下一月扣神识 5，但预约时随身仍是 488 灵石，未扣钱或跑月。

**T72035／7003 年十一月，闻春岚在原寒玉井实付 2 灵石，钱包降至 486，真实勘得井深 24。** 同月无订单对照仍为 488。预约核销，没有新开天门或改旧水债。原档未动；预约帧和勘完帧分别实际写出独立严格便携档，从盘另读并复演下一月都同字节。实际同日外来快照、仅名字、真实已故异人均不能偷换进入资格。自然六千年原档没有同名者；另在隔离的早年原生场景只给一名真实不同 ID 的角色换成一样显示名，仍不能替选定角色排令。此隔离负例不写进六千年原档，也不声称自然出现了同名。

本轮只做云端原生程序与有成本的真实行动，不是手机真机测试，不增加首页入口，也未改现有手机试玩。
